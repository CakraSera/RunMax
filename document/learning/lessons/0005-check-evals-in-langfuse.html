Lesson 0005 · Evals in Langfuse

Check evals in Langfuse, step by step

The report card has two halves: the terminal tells you pass/fail, Langfuse shows you how each robot ran. This lesson walks both.

First, know what you will see

Each eval case is one Langfuse trace named BuildThisWeek (board evals) or ConsultThenBuild (consult evals). Inside every trace: the AGENT root, one GENERATION per model turn, one TOOL per tool call (parseLog, retrieveNotes, draftWeek, checkWeek, saveWeek). Evals run at effort: "low" — that is why they are faster and cheaper than a real build.

The pass/fail verdict lives in the terminal, not Langfuse: the oracle is pure rules (checkWeek) checked in-process. Langfuse is the evidence — the film of every run behind each verdict. (Langfuse evaluation overview.)

Part 1 — run the evals

  1. Terminal: pnpm --filter @runmax/agent evals — 10 board cases, ~4 min (real model).
  2. Read the lines as they finish: eval pain-lutut ... PASS. Expect 10/10 passed.
  3. Consult evals: pnpm --filter @runmax/agent evals:consult — 3 cases. Expect 3/3 passed.
  4. One case only (fast loop): append its id — e.g. pnpm --filter @runmax/agent evals pain-lutut.

Every case id is a fixture name you can quote in the presentation: happy-en, pain-lutut, two-hard-draft, no-rest, empty-log, quality-no-pace, mixed-id-en, board-has-seven, second-build-overwrite, sakit-no-dx.

Part 2 — find the runs in Langfuse

  1. Open us.cloud.langfuse.com → your project → Traces.
  2. Time filter: last 24 hours. Clear every other filter (environment, type, tags).
  3. Search name BuildThisWeek — you will see a fresh cluster, one trace per eval case, all with sessionId demo.
  4. Open one trace, e.g. pain-lutut's run. Check the hierarchy:
    • Root type AGENT (not Span — lesson 0001 explains why this can go wrong).
    • GENERATION turns showing model z-ai/glm-5.3-flash and token usage.
    • TOOL children in order: parseLog → retrieveNotes → draftWeek → checkWeek → saveWeek.
  5. Click saveWeek's input/output — that is the exact Week the teacher approved for this fixture.
  6. For a pain case (pain-lutut, sakit-no-dx): open draftWeek's output and point — “zero quality days, because knee.” That is your demo line.

The 60-second presentation move

“We have 13 golden fixtures. The terminal says 13 for 13. And here —” (open Langfuse, click one trace) “— is the film of one of them: the robot read the diary, borrowed coach notes, drew the week, the teacher checked it, and saved. Every step filmed.”

If a trace is missing

Work the checklist from the debug reference: printed traceId → API lookup → UI filters. Remember lesson 0001: flush succeeding is not proof a row exists.

Check yourself

2. Ten board cases produce how many BuildThisWeek traces?

3. Why do evals run faster than a real build?
